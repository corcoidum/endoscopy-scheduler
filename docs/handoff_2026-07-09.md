# 2026-07-09 작업 인수인계 메모

이 문서는 오늘 Codex와 논의한 내용을 내일 다른 PC, 특히 Mac에서 이어서 작업하기 위한 handoff 문서다.
실제 환자정보, 실제 예약 데이터, `.env` 값, 운영 비밀번호는 포함하지 않는다.

## 현재 프로젝트 요약

- 프로젝트명: `endoscopy-scheduler`
- 목적: 원내 내시경 예약 및 스케줄 관리용 내부 웹앱
- 저장소: `https://github.com/corcoidum/endoscopy-scheduler.git`
- 현재 스택:
  - Backend: FastAPI
  - Template/UI: Jinja2 + HTMX + 단순 CSS
  - ORM/Migration: SQLAlchemy + Alembic
  - DB: 개발 SQLite, 운영 PostgreSQL 권장
  - 테스트: pytest, 일부 Playwright E2E

현재 구조는 MVP 수준으로 잘 잡혀 있다. 다만 `app/routers/appointments.py`가 화면 렌더링, validation, DB mutation, 감사 로그까지 많이 맡고 있어서 앞으로 기능이 늘면 분리가 필요하다.

## 오늘 논의한 핵심 방향

원내 직원들이 함께 쓰는 예약 관리 앱이지만 EMR 대체가 아니다. 예약 운영에 필요한 최소정보만 저장하고, 상세정보 접근과 변경 이력은 개인 계정 기준으로 남기는 방향이 적절하다.

기본 원칙:

- 내부망 또는 VPN에서만 접속
- 직원별 개인 계정 사용, 공동 계정 금지
- 상세 조회, 검색, 수정, 취소, 출력, CSV export는 audit log 기록
- 공용 화면에는 최소정보와 마스킹 정보만 표시
- 실제 환자 데이터는 개발 DB와 테스트 DB에 복사하지 않음
- 외부 AI API, 광고/분석 스크립트, 외부 spreadsheet 자동 동기화 금지
- 백업 파일 암호화, 파일명에 환자정보 금지

참고 자료:

- 개인정보보호위원회 안내서 목록: `개인정보의 안전성 확보조치 기준 안내서(2025.11.)`, `보건의료데이터 활용 가이드라인(2025.12.)` 확인 필요
- URL: https://www.pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=D010030000

## 사용자가 추가로 넣고 싶은 운영 필드

내부 웹에서 최소 운영 필드로 다음 항목을 넣고 싶다고 정리했다.

환자 기본정보:

- 차트번호
- 이름
- 나이
- 성별

예약 및 검사 정보:

- 예약일
- 위/대장내시경 구분
- 검진유무
- 수면유무
- 본인부담: 없음 / 10%
- 일반검진 진행여부
- 분변검사유무
- 예약금
- 정결제 종류: 이지프렙 / 수클리어산 / 수프렙미니에스산
- 초음파 진행여부: 복부 / 갑상선 / 경동맥 / 심장
- 혈액순환제 복용유무
- 중단약 메모란

주의:

- `중단약 메모`는 자유 입력이므로 민감정보가 섞일 위험이 높다.
- 화면에는 "주민등록번호, 전체 전화번호, 진단명, 검사결과는 입력하지 마세요." 안내가 필요하다.
- 감사 로그에는 메모 원문을 저장하지 않고 `[masked]` 또는 `[recorded]`로 처리한다.

## 권장 데이터 모델 방향

`patients_minimal`에는 식별 최소정보만 둔다.

```text
chart_number
patient_name
age
sex
```

예약 관련 정보는 `endoscopy_appointments`에 둔다.

```text
appointment_date
appointment_time
endoscopy_type
is_health_checkup
sedation
copay_type
general_checkup_status
fecal_test_status
deposit_amount
bowel_prep_type
ultrasound_abdomen
ultrasound_thyroid
ultrasound_carotid
ultrasound_cardiac
takes_circulation_medication
medication_stop_note
medication_check_required
```

가능하면 enum 또는 제한된 선택값을 사용한다. 자유 텍스트는 `medication_stop_note`, 운영 메모처럼 꼭 필요한 곳에만 둔다.

app/

추천 순서:

2. 예약 validation과 조회 query를 `services/`로 분리
3. 관리자 라우터를 기능별로 분리
4. 모델 분리는 마지막에 검토

## UX 개선 방향

원내 공유 UX는 "모두가 같은 예약 현황을 보되, 각 직원은 자기 업무에 필요한 정보만 빠르게 보게 하는 구조"가 좋다.

역할별 화면:

- 공용 업무판: 마스킹 이름, 차트번호 일부, 나이/성별, 검사종류, 수면, 정결제, 초음파, 준비상태
- 접수 화면: 예약일, 예약금, 검진유무, 본인부담, 일반검진 진행, 분변검사 상태
- 검사실/간호 화면: 검사종류, 수면, 정결제, 초음파, 혈액순환제 복용, 중단약 메모, 준비상태
- 관리자/원장 화면: 전체 상세, 예외 수정, 감사 로그, 보존정책, 백업

예약 등록 화면은 긴 폼 하나보다 아래 구역으로 나누는 것이 좋다.

```text
1. 환자 기본정보
2. 검사 예약
3. 검진/비용
4. 추가검사
5. 약제 확인
```

메인 화면에는 `확인 필요` queue를 둔다.

```text
정결제 미확인
혈액순환제 복용 있음
중단약 메모 있음
분변검사 미회수
검진 진행 미완료
예약금 미확인
보호자/수면 관련 확인 필요
```

## 내일 이어서 할 작업 순서 제안

1. 새 필드 추가 범위를 확정한다.
2. `models.py`와 Alembic migration 설계를 먼저 만든다.
3. `schemas.py` 또는 form parsing에 새 필드를 반영한다.
4. 예약 등록/수정 template을 5개 구역으로 나눈다.
5. 오늘 업무판에 확인 필요 queue를 추가한다.
6. audit redaction 대상에 `medication_stop_note`, `deposit_amount`, `patient_name`, `chart_number` 등을 반영한다.
7. `pytest tests\test_privacy_and_ops.py tests\test_appointments.py`를 실행한다.

## Mac에서 이어서 작업하는 방법

처음 clone하는 경우:

```bash
git clone https://github.com/corcoidum/endoscopy-scheduler.git
cd endoscopy-scheduler
git checkout codex/add-handoff-notes
```

이미 clone한 경우:

```bash
cd endoscopy-scheduler
git fetch origin
git checkout codex/add-handoff-notes
```

브랜치가 main에 merge된 뒤에는:

```bash
git checkout main
git pull
```

Python 환경은 Mac에서 다시 만든다.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
uvicorn app.main:app --reload
```
